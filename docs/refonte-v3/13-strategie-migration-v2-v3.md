# Strategie de migration V2 vers V3

Approche :

1. geler un etat de reference ;
2. corriger les risques critiques ;
3. definir contrat et IDs canoniques ;
4. poser design tokens et composants ;
5. migrer une verticale pilote ;
6. etendre par lots ;
7. valider route, contenu, progression, SEO, accessibilite et performance a chaque lot.

Interdits :

- suppression massive ;
- changement simultane routes + donnees + design + progression ;
- deux sources de verite permanentes ;
- migration de progression destructrice ;
- refonte scientifique sans revue ;
- dependance inutile.

Procedure de retour arriere :

- garder les routes legacy ;
- isoler les prompts par zones ;
- ne supprimer les anciennes lectures de progression qu'apres plusieurs versions ;
- conserver des snapshots de contenu et de routes.
